# Homepage

Source of **[jooyounghahn.github.io](https://jooyounghahn.github.io)**, the academic
homepage of Jooyoung Hahn (Czech Technical University in Prague).

Content lives in `data/` and `assets/`, the design lives in `build/theme.py`, and
`build/render.py` turns them into `docs/`, which GitHub Pages serves. Nothing is
written twice.

```
  data/content.json        profile, intro, opening notice, research categories,
                           per-paper figure + one-line synopsis
  data/publications.json   publication list (checked against Crossref)
  data/talks.json          invited talks, minisymposia (from the CV)
  data/interests.json      research-interest topics: label, description, figure
  data/papers.json         title and year per paper, from build/scan_papers.py
  assets/photo.jpg         profile photo
  assets/heroes/           one 4:3 image per research category
  assets/paperfigs/        one figure per paper
  assets/interests/        one generated figure per topic (PNG; published as WebP)
                           + src/<id>.py that made it (run it to regenerate)
            |
            |  python build/render.py
            v
  docs/                    index.html (Research) · interests.html
                           publications.html · talks.html
```

`docs/` is wiped and rebuilt on every run. Never edit it by hand.

## Pages

| Page | Source |
|---|---|
| Research (home) | `content.json`: `intro`, `notice`, `categories`, `papers` |
| Research interests | `interests.json` |
| Publications | `publications.json`, four tabs: journal, conference, preprint, patent |
| Talks | `talks.json` |
| CV *(off)* | copied at build time from the CV folder; see below |
| Open position *(off)* | copied at build time from the PhD flyer; see below |

The CV and the flyer are **not published at the moment**: `build.cv_link` and
`build.opening_link` in `content.json` are `false`, so neither file is copied and
neither menu item appears. Set one to `true` and rebuild to publish it. Both are
copied fresh on every build, so updating the original and rebuilding is enough.

## Common edits

- **Intro text:** `content.json` → `intro`.
- **Opening notice on the home page:** `content.json` → `notice`. After the `until`
  date it hides itself. To remove it for good, delete `notice`.
- **A new paper:** add it to `publications.json`. To list it on the Research page too,
  put the PDF, `.md` and `.assets/` in the paper archive, run
  `python build/scan_papers.py`, add its key to a category in `content.json`, and give it
  a `figure_src` (a JPEG in `assets/paperfigs/`) and a `synopsis`.
- **A new talk:** add it at the top of `talks.json` → `invited` or `minisymposia`.
- **A research-interest topic:** add an entry to `interests.json` → `topics`. Its
  `group` must be one of `groups`, and its `figure` is a path under `assets/interests/`.
- **Last-updated line:** `content.json` → `build.updated`.

Then:

```sh
python build/render.py
```

## Design

Everything visual is in `build/theme.py`: the `PALETTE` dict (light and dark) and one
stylesheet. The palette is *Meridian: Sky & Ink*. It uses a sky-tinted sidebar, navy ink
and one steel blue for links. A cold carmine is used **only** as a marker, on the
active navigation item and on the rule beside the opening notice.

The layout depends on the screen:

- **900 px and wider, and at least 560 px tall:** a sticky sidebar holds the photo, name,
  group, navigation and profile links. The page is centred, and the sidebar tint runs to
  the left edge.
- **Otherwise (phones, portrait tablets, phones in landscape):** a compact header sits
  above a sticky tab strip that scrolls sideways. The profile links move to the footer.

The generated topic figures use one shared style (the palette above, white background,
large type) so that they read as one set. See `assets/interests/src/`.
**Every generated image carries "Generated by AI" bottom-right inside the image.**
`figstyle.save()` adds it automatically. This is a rule for the whole folder; see
[CLAUDE.md](CLAUDE.md).

## Publishing

The repo is served by GitHub Pages from the `docs/` folder on `main`
(*Settings → Pages → Deploy from a branch → main → /docs*). Every update is:

```sh
python build/render.py
git add -A && git commit -m "update" && git push
```

The new version is live a minute or so later. If the address ever changes, update
`build.site_url` in `content.json`; it is used for the canonical and share-preview links.

## Notes

- On the four generated pages the email address never appears as a string. JavaScript
  assembles it on click.
- The build is all-or-nothing. If an input or figure is missing, `render.py` stops,
  lists the problems and leaves `docs/` unchanged. It only ever writes to a subfolder
  of this repo.
- `data/papers.json` and `assets/thumbs/` are generated by `scan_papers.py`. Do not
  hand-edit them. `scan_papers.py` also writes `data/papers.local.json`, which holds
  abstracts and author e-mail addresses from the archive and is never published.
- `build/_retired/` holds the old single-page editor and is not used.
- The paper figures come from the author's own publications and are shown here as
  part of an academic homepage.
